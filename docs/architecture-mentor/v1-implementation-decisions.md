## 1. 定位与变更规则

本文档把 README 中"尚未确认的实现决策"在 v1 范围内逐一给出归宿：**已决定**（D1–D11）、**延后**（试点验证中 / v2）或**保持开放**。决策依据全部指向 owning 设计文档，不引入新的语义设计。

变更规则：

- D1–D11 的任何变更必须更新本文件与实施计划，并重新获得用户确认；
- owning 设计文档变化时，本文件须同步校正，防止文档与决策漂移。

## 3. 由决策派生的 v1 硬约束

1. 安装器只写 `$DSH_HOME/.agent-presets/architecture-mentor/`；覆盖前备份；目标存在但无本仓库 `VERSION` 时拒绝；绝不触碰 shipped 预设目录（工程化设计 §1、§4）。
2. 运行时门禁零脚本：只由记录模板必填字段 + 技能内检查清单 + git 审计承载；本仓库允许的脚本仅限安装器、身份生成器与构建期冒烟测试（编写规范 §2）。
3. 技能 frontmatter `name` 必须 kebab-case 且与目录名一致；`description` 覆盖"何时用 / 做什么 / 何时不用或需用户确认"（编写规范 §4）。
4. 导师人格分层：L0 persona 约 2–4 KB；L1 AGENTS.md 目标 ≤ 16 KB（上限 64 KB）；L2 技能不常驻；L3 按需读取（工程化设计 §6）。
5. 初始化写入工作区文件前需用户确认；技能永不复制进工作区（工程化设计 §5）。
6. 事实类记录（Experience/Evidence）不改写原文；解释类记录通过 `superseded`/`supersedes` 显式替代（记忆生命周期、编写规范 §7.4）。
7. 本次执行范围 M0–M4；试点（M5）与发布（M6）须用户重新发起。
