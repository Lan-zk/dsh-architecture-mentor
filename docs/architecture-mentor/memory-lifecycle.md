# 记忆生命周期与活跃上下文

## 生命周期目标

长期记忆不是永久有效的事实集合。记录是否继续影响当前教学，取决于它是否仍有 Future Decision Value（未来决策价值）：能否改变导师下一步教什么、挑战什么、默认什么或警惕什么。

生命周期负责处理三个问题：

1. 新观察何时足以影响教学；
2. 新证据与旧判断冲突时如何处理；
3. 哪些内容退出活跃上下文、进入归档或被删除。

## v1 生命周期状态

```text
candidate ──验证充分──→ active
    │                    │
    │证据不足             │出现冲突证据
    ↓                    ↓
 archived            challenged
                         │
              ┌──────────┴──────────┐
              │旧判断仍成立          │新解释更准确
              ↓                     ↓
            active              superseded
                                      ↓
                                  archived
```

### `candidate`（候选）

刚观察到一个可能影响教学的现象，但证据不足。候选记录用于提醒导师验证，不允许直接提升或降低稳定能力结论。

### `active`（活跃）

已有足够证据支持，当前仍应影响教学决策。活跃不等于绝对正确，仍可被后续证据挑战。

### `challenged`（受质疑）

新 Evidence（证据）开始与当前判断冲突。导师应主动设计验证，既不能忽略反证，也不能因为一次新表现立即删除历史判断。

### `superseded`（已替代）

新的解释或能力状态比旧记录更准确。旧记录保留历史意义，并显式指向替代它的新记录，不再作为当前权威。

### `archived`（已归档）

记录已经不值得默认影响当前教学，但仍有追溯、成长历史、反例或重新引入价值。归档内容按需检索，不进入默认工作集。

状态名称是 Memory Model v1 的工作约定。具体转换阈值仍需通过实际使用验证。

这些状态描述的是一条记忆记录是否仍值得影响当前教学，不描述学习者的能力高低。`active`（活跃）不等于“已掌握”，`challenged`（受质疑）也不自动等于“能力退化”。能力证据覆盖范围由 [《能力与证据模型》](./capability-evidence-model.md) 单独描述。

生命周期转换本身不是学习流程。只有写入长期 Evidence、提升 Capability State 或修改 Mentoring Contract 时需要强制门禁；普通记录退出活跃工作集、按需检索归档内容等操作不应要求学习活动停下来完成一套审批流程。

## 不同记忆类型的更新方式

生命周期不能被理解为“所有记录都可以随意改写”。不同类型的更新语义不同：

- **Experience（经历）和 Evidence（学习证据）**记录当时发生的事实，应尽量保持不可变。发现记录错误时追加更正和来源，不把过去改成现在的结论。它们可以退出活跃上下文，但事实本身通常不被新事实“替代”。
- **Hypothesis（导师假设）**可以被激活、质疑、替代或归档，因为它本来就是可证伪解释。
- **Capability State（能力状态）**是某个时间点的证据摘要。新状态应引用旧状态并明确替代关系，以保留能力变化轨迹。
- **Architecture Insight（架构经验）**可以因新案例被质疑、细化或替代；适用边界变化时不能静默改写成另一条原则。

核心规则是：

> Evidence（证据）保留当时发生了什么；Interpretation（解释）允许改变，但改变必须可追溯。

## 禁止静默重写

旧记录被新判断取代时，不能直接把旧文件改成新意思。例如，过去一次设计确实遗漏了 Idempotency（幂等性）风险，半年后的进步不能抹掉这项历史事实。

正确方式是：

```text
旧 Evidence：当时没有识别幂等风险。

新 Evidence：后来三个案例都主动识别。

旧 Hypothesis：superseded by H-0037。

新 Hypothesis：已具备基础识别能力，
当前更需要训练复杂 Retry Boundary（重试边界）判断。
```

部分替代时，应保留仍成立的部分并交叉引用。旧记录如果仍能阻止一个诱人但错误的决定，也可以继续保留其反例价值。

## Active Memory 的预算

导师不能在每次启动时读取全部对话、案例和学习记录。Active Memory（活跃记忆）应作为一个有容量预算的 Working Set（工作集），默认只包含：

- 当前长期目标和现实约束；
- 当前最重要的 Capability State（能力状态）；
- 少量仍在验证的 Hypothesis（导师假设）；
- 最近且高价值的 Evidence（学习证据）；
- 与当前任务直接相关的 Architecture Insight（架构经验）；
- 最近采用的教学策略及其效果；
- 已知会显著影响当前判断的反例或旧误区。

其他内容进入 Archive（归档），在当前任务、假设验证或历史追溯需要时 Retrieval（按需检索）。

Active 不应等于“最近”。选择工作集时至少考虑：

- 与当前教学决策的相关性；
- 证据质量和可追溯性；
- 是否仍在验证；
- 错误使用它的风险；
- 是否已有更准确记录替代；
- 不读取它是否可能重复重要错误。

工作集的具体容量、排序算法和检索方式在 V1 以试点参数承载（`active-context.md` ≤ 8 KB，排序 = 决策价值 × 证据质量 × 误用风险），待试点校准。

## 归档、降级与删除

归档用于把有历史或潜在检索价值的内容移出默认上下文。删除则适用于不再值得保留的噪声或无依据派生内容。

可以考虑删除或降级：

- 无法追溯来源的导师判断；
- 重复记录；
- 已被新证据完整替代、且没有历史价值的派生总结；
- 一次性教学过程细节；
- 对未来教学没有价值的普通对话总结；
- 已失效的临时目标或兴趣状态。

Experience（经历）和 Evidence（学习证据）涉及成长历史和审计价值时，应优先归档而不是删除。任何删除机制都必须有明确作用域，不能为了压缩上下文破坏关键证据链。

遗忘不是记忆系统的缺陷，而是保持长期判断质量的一部分。

## 避免学习记录债务

不应在每次对话结束后自动生成一条长期 Learning Record（学习记录）。一条经历只有在可能改变未来教学起点、挑战方式、能力状态、诊断假设或可复用经验时，才值得进入长期记忆。

其他内容可以保留在原始历史中。减少长期记录数量不是丢失学习，而是在保护 Active Memory 的信噪比。
