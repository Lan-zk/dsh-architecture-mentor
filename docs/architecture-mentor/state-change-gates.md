# 长期状态变更门禁

## 目的

长期状态变更门禁用于限制“导师准备长期相信什么”，而不是规定“导师这次必须怎样教学”。它保护证据质量、能力判断和用户目标，同时保留导师根据上下文自由选择学习策略的空间。

Memory Model v1 只对三类高影响动作设置强制门禁：

1. 写入长期 Evidence（学习证据）；
2. 提升 Capability State（能力状态）；
3. 修改 Mentoring Contract（导师契约）。

除此之外，提问、讲解、代码调查、案例比较、反事实推演、临时工作假设、原始历史保存和普通策略切换，不要求执行统一流程。

## 门禁一：写入长期 Evidence

学习活动或对话已经发生，不代表必须生成长期证据。只有一项表现可能改变未来教学起点、诊断或挑战方式时，才值得尝试写入。

写入长期 Evidence 前必须能够回答：

- 对应的 Experience（经历）和原始产出是什么；
- 实际观察到的学习者行为是什么，而不是导师对人格的评价；
- 当时的业务、技术和组织上下文是什么；
- 学习者接受了多少提示或 AI 协助；
- 证据支持哪项能力或反驳哪项假设；
- 是否存在明显 Counterevidence（反证）；
- 为什么这条记录对未来教学仍有价值；
- 来源是否可追溯，未来能否重新评估。

门禁通过只表示这是一条合格的长期 Evidence，不表示已经掌握某项能力。单次合格证据仍然可以只支持一次局部表现。

不满足门禁的内容可以保留在 Raw History（原始历史）或 Experience（经历）中，但不能伪装成长期能力证据。

## 门禁二：提升 Capability State

Capability State 的“提升”包括提高证据覆盖阶段、提高稳定性置信度，或把“尚未证明”改为“已经证明”。

提升前必须满足：

- 明确指出被提升的具体能力维度和适用范围；
- 引用通过长期 Evidence 门禁的证据；
- 说明证据覆盖 Exposure、Explain、Recognize、Decide、Predict 或 Transfer 中的哪个阶段；
- 区分 Single-case、Repeated 和 Cross-context Evidence；
- 说明提示程度、结果校准情况和时间稳定性；
- 检查是否存在仍未解决的冲突证据；
- 保留尚未证明的部分，不能用一个总等级掩盖能力差异；
- 记录旧状态及显式替代关系。

高置信度 Transfer（迁移）声明必须有跨场景证据，不能由一次成功、重复解释或同构案例直接推出。

能力状态可以因新证据被质疑、细化或降低置信度。这些更新同样需要可追溯依据，但“受质疑”不自动等于能力退化。

具体升级阈值和是否需要独立评估者仍待验证。

## 门禁三：修改 Mentoring Contract

修改长期目标、当前训练范围、现实约束、工作模式或导师权限，会改变系统优化方向，因此必须由用户拥有最终确认权。

修改前必须：

- 明确旧契约和建议的新契约；
- 说明触发修改的现实变化或新证据；
- 区分“导师建议”和“用户决定”；
- 获得用户明确确认，或验证已有授权确实覆盖本次修改；
- 记录生效时间和替代关系；
- 评估是否需要中止、调整或继续当前教学活动。

导师可以主动建议修改，但不能因为自己的 Hypothesis 或 Capability State 自动修改契约。

## 门禁不等于固定学习流程

以下做法违反本设计：

- 每次对话都重新填写导师契约；
- 每次学习活动都生成五类长期记录；
- 每次策略选择都填写完整审批记录；
- 每次教学都按“诊断—练习—反馈—迁移”执行；
- 按能力阶梯顺序安排固定课程；
- 为了满足记录字段而中断当前高价值探索。

正确关系是：

```text
导师自由选择学习策略
          ↓
产生观察、产出或临时判断
          ↓
是否准备改变长期状态？
      ├─ 否：继续教学，不触发门禁
      └─ 是：只执行对应的状态变更门禁
```

## 执行责任仍待决定

门禁规则已经确认，但执行架构尚未确定。可能的实现包括：

- 导师执行并在写入前自检；
- 独立 Validator（校验器）复核高影响变更；
- 普通 Evidence 由导师校验，高置信度 Capability 或契约变更由独立角色复核；
- 由结构化存储或自动检查阻止缺少来源和替代关系的写入。

选择实现方式时，应以低摩擦和可复核为目标，不能让门禁自身演变成主要工作负担。
