# 长期记忆模型

## 设计目标

Workspace（工作区）可以保存对话、项目分析、设计、决策和学习记录，但“保存过的信息”不自动等于 Memory（记忆）。记忆只包含未来导师可能据此改变教学行为的信息，例如改变教学主题、挑战重点、默认能力基线、对误区的警惕程度或对某种教学策略的选择。

因此：

> Raw History（原始历史）可以很多，Active Memory（活跃记忆）必须少而高价值。

完整历史负责保真和追溯；长期记忆负责形成证据链；活跃记忆负责支持当前教学决策。是否保持活跃取决于 Future Decision Value（未来决策价值），而不是记录年龄、文件大小或对话是否发生过。

用户拥有的长期目标、现实约束和导师权限不属于这五类学习记忆，而由 [Mentoring Contract（导师契约）](./mentoring-contract.md) 单独维护。导师可以依据记忆提出契约修改建议，但不能用派生判断覆盖用户确认的契约。

## 原始历史与记忆的边界

原始历史包括未经筛选的对话、代码位置、提交、PR、设计草稿、链接、即时想法和实现结果。它们可以保存，但默认不进入当前上下文，也不直接改变学习者模型。

Experience（经历）是从原始历史中提取出的、值得长期引用的事实单元。例如“完成了一次架构评审”过于宽泛；“在某次评审中，学习者提出了异步化方案，后续运行结果暴露出顺序问题”才可能成为可追溯的经历记录。

换言之：

```text
所有保存内容 ⊃ 原始历史 ⊃ 被筛选的 Experience（经历）
                                    ↓
                              可能产生 Evidence（证据）
```

## 五类长期记忆

| 类型 | 回答的问题 | 典型内容 | 关键限制 |
| --- | --- | --- | --- |
| Experience（经历） | 发生了什么？ | 项目、评审、事故、设计、实现结果、研究活动 | 只陈述可追溯事实，不能直接推出掌握程度 |
| Evidence（学习证据） | 学习者实际表现出了什么？ | 独立识别的约束、做出的判断、预测、结果、纠错和迁移表现 | 描述行为而非人格；记录提示程度、上下文和来源 |
| Hypothesis（导师假设） | 导师暂时怀疑哪里强、哪里弱？ | 可能方案先行、可能忽略运行故障、某种教学方式可能有效 | 始终可证伪；不是事实；必须引用证据 |
| Capability State（能力状态） | 某项能力目前被证明到什么程度？ | 已证明、尚未证明、证据强度、当前状态 | 只总结证据覆盖范围，不把未知写成不会 |
| Architecture Insight（架构经验） | 哪条判断原则未来值得复用？ | 原则、适用条件、权衡、成本、替代方案和反例 | 属于知识，不证明学习者已经掌握 |

Learner Model（学习者模型）主要由 Hypothesis（导师假设）和 Capability State（能力状态）构成。前者表达待验证诊断，后者表达证据目前支持到哪里。把两者分开，可以避免“导师怀疑存在问题”被误写成“学习者已经被证明不会”。

## 信息关系

```text
Raw History（原始历史）
        ↓ 筛选出有未来价值的事实
Experience（经历）
        ↓ 观察学习者行为与结果
Evidence（学习证据）
        ├────────→ Hypothesis（导师假设）
        │                 ↓ 后续案例验证或反驳
        └────────→ Capability State（能力状态）
                              ↓
                    Mentoring Decision（教学决策）
                              ↓
                    New Experience（新经历）
                              └──────────────↺

Architecture Insight（架构经验）
来自案例与外部知识，参与教学和校准，
但不能直接证明学习者已经掌握。
```

正确的更新链路是：

```text
Experience
  → Observed Behavior
  → Evidence
  → Hypothesis
  → 后续验证
  → Capability State 更新
```

禁止的更新链路是：

```text
导师过去的判断
  → 被下一次导师读取
  → 作为证明原判断正确的新证据
```

导师的判断不能成为证明导师判断正确的证据。

## 证据驱动的学习者模型

每一条长期能力判断都必须能追溯到具体 Evidence（学习证据）。例如，不能只保存“学习者不擅长领域建模”，而应保存一个可证伪假设，并引用它依据的案例：学习者当时怎样拆分边界、接受了多少提示、后来是否在新案例中改变了做法。

只有 Evidence（学习证据）可以改变 Learner Model（学习者模型）。以下内容不能单独成为能力证据：

- 导师过去写下的能力评价；
- AI 给出的答案或总结；
- 某个主题在对话中出现过；
- 学习者表示自己理解了；
- 一份材料被收藏、阅读或讲解过；
- 工作区中已经存在某条架构知识。

详细的证据强度和能力阶梯见 [《能力与证据模型》](./capability-evidence-model.md)。

一次观察只有通过 [长期 Evidence 写入门禁](./state-change-gates.md#门禁一写入长期-evidence)，才能进入长期证据集。未通过门禁不表示内容必须删除，它仍可保留为原始历史或经历。

## Architecture Insight 的质量要求

架构经验不能写成“微服务适合大型系统”之类脱离条件的口号。一条值得进入高置信度知识库的 Insight（经验）至少应说明：

- Context（上下文）与适用条件；
- Forces（作用力/约束）与目标；
- Decision（判断）及其理由；
- Trade-off（权衡）与主要成本；
- Alternatives（替代方案）；
- Counterexample（反例）或不适用条件；
- 什么变化会触发重新评估。

工作区里存在一条高质量 Insight，只能证明系统保存了这条知识，不能证明学习者具备独立调用它的能力。

## 八条记忆不变量

1. **导师判断不是证据。只有学习者行为、项目结果和可验证产出才可能成为证据。**
2. **所有长期能力判断必须可追溯到 Evidence（学习证据）。**
3. **Evidence 记录发生过什么；Interpretation（解释）允许以后被推翻。**
4. **单次成功不等于掌握；跨场景 Transfer（迁移）是高置信度能力证据。**
5. **工作区里存在某项知识，不代表学习者已经掌握。**
6. **旧判断不得静默重写，必须明确替代、降级或归档。**
7. **只有仍会影响未来教学决策的内容保持 Active（活跃）。**
8. **记忆的目标不是完整记录过去，而是提高未来导师判断的质量。**

生命周期、活跃工作集和遗忘规则见 [《记忆生命周期与活跃上下文》](./memory-lifecycle.md)。
