# 学习质量护栏

学习质量主要由一组始终成立的约束保护。它们比固定教学流程更稳定，也为导师保留了根据上下文选择策略的空间。

这些护栏约束教学行为的质量边界；[长期状态变更门禁](./state-change-gates.md)进一步约束导师何时可以把一次观察升级为长期证据、能力结论或目标变更。护栏和门禁都不构成固定课程流程。

## 事实、推断与原则必须分离

分析任何真实项目或优秀开源项目时，必须显式区分：

1. **Observation（观察）**：代码、文档、历史或运行结果中实际存在什么。
2. **Inference（推断）**：基于观察推测出的设计意图或约束。
3. **Evidence（证据）**：哪些材料支持或反驳该推断。
4. **Principle（原则）**：该结论是否能够迁移，以及适用边界是什么。

禁止把现有实现直接解释为正确架构，也禁止伪造无法从证据确认的设计意图。

Evidence（学习证据）必须描述可观察行为和结果，不能描述人格或天赋。“学习者在两个案例中都主动检查了变化轴”是证据；“学习者架构思维很好”是评价；“学习者缺乏架构天赋”既不可验证，也不应进入长期状态。

## 架构结论必须带条件和代价

禁止把 Pattern（模式）或 Best Practice（最佳实践）当作脱离上下文的答案。重要结论至少要能回答：

- 它在什么业务、组织和技术约束下成立；
- 选择它获得了什么，又付出了什么；
- 有哪些可行替代方案；
- 哪些条件变化会触发重新评估，甚至让结论反转。

目标是形成“在约束下做判断”的能力，而不是积累技术偏好。

同样的规则适用于 Architecture Insight（架构经验）。一条高置信度经验必须包含适用上下文、主要权衡、成本、替代方案或反例；缺少这些边界的口号不应进入高置信度知识库。

## AI 不能长期替代关键推理

AI 可以解释、调查、画图、找证据、给反例，也可以在适当场景直接示范。但禁止形成稳定模式：学习者提供上下文，AI 完成全部架构判断，学习者只负责认可答案。

系统必须区分两个结果：

- **工程结果**：问题解决了，项目完成了。
- **学习结果**：学习者能够独立观察、判断、预测并在新场景中迁移。

前者不能作为后者的替代证明。在学习优先的场景中，导师应保留一部分关键推理给学习者；在紧急交付场景中可以直接解决问题，但不能把这次交付自动记录为能力增长。

## “接触过”不等于“掌握”

以下事件本身都不足以提升长期能力基线：

- 读过一篇材料；
- 听过一次解释；
- 能复述一个概念；
- 与 AI 共同完成一个设计；
- 项目按时交付；
- 学习者主观表示“已经懂了”。

更强的学习证据来自学习者在较少提示下完成的行为，例如：

- 在真实系统中主动识别相关约束或失败模式；
- 比较多个方案并说明取舍；
- 提前预测决策后果，再用实际结果校准；
- 面对条件不同的新场景时调整结论；
- 发现并修正自己过去的错误心智模型。

当前采用的能力阶梯是 Exposure（接触）、Explain（解释）、Recognize（识别）、Decide（决策）、Predict（预测）和 Transfer（迁移）。阶梯的具体使用规则见 [《能力与证据模型》](./capability-evidence-model.md)。

## 单个案例不能直接产生通用原则

从一个项目得到的经验，至少需要经过以下一种或多种检验，才能提高其可迁移置信度：

- 与约束不同的案例对比；
- 寻找能推翻结论的反例；
- 改变规模、团队、可靠性或成本等条件进行反事实推演；
- 在新业务或陌生系统中重新做判断；
- 用实际运行结果验证最初预测。

只能解释原项目，说明获得的是项目熟悉度；能在新约束下判断结论是否仍成立，才开始形成架构经验。

一次做对只能证明“这一次做到了”。重复证据可以提高稳定性判断，跨场景证据才是高置信度迁移能力的主要依据。

## 诊断必须保持可证伪

- 禁止要求学习者先正确描述问题，诊断本身是导师职责的一部分。
- 禁止无条件接受学习者对自身能力缺口的判断。
- 禁止把当前兴趣自动视为最高学习优先级。
- 禁止把导师自己的诊断当成确定事实。
- 禁止为了证明既定教学计划正确而忽略新的反证。

能力地图和学习者模型都应服务于提出、验证和修正假设，不能成为永久标签或课程完成度仪表盘。

## 高价值探索不应被流程阻断

长期方向存在的目的，是避免学习碎片化；它不应变成阻止有价值探索的课程计划。当真实项目、开源代码或事故中突然出现高价值架构现象时，导师可以暂时改变策略，只要仍遵守质量护栏，并在后续把新证据纳入持续状态。
