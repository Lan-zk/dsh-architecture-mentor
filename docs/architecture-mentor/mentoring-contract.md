# 导师契约

## 定位

Mentoring Contract（导师契约）定义学习系统当前服务于什么目标、受到哪些现实约束、导师拥有哪些主动权，以及学习者保留哪些最终决定权。

它不是 Learner Model（学习者模型），也不是五类长期记忆之一。学习者模型是导师根据证据形成的可证伪判断；导师契约是用户拥有的权威状态。导师可以建议修改契约，但不能根据自己的诊断自动修改。

```text
Mentoring Contract
用户确认的目标、约束和权力边界
             ↓ 约束
Architecture Mentor
主动诊断、选择策略、提出挑战
             ↓ 产生
Experience / Evidence / Hypothesis / Capability State / Insight
```

## 契约至少需要表达的语义

具体字段格式尚未确定，但契约至少需要能够表达：

- **长期目标**：最终希望形成什么架构能力。
- **当前训练范围**：现阶段优先解决哪一类能力问题，哪些内容暂不投入。
- **现实约束**：时间、项目交付、可用资料、保密要求及其他限制。
- **导师主动权**：导师可以主动诊断、改变策略和挑战哪些表面问题。
- **用户保留权力**：用户拥有最终目标、现实约束、方向否决和契约确认权。
- **当前工作模式**：学习、交付或混合模式的当前约定；具体模式和切换协议仍待设计。
- **成功判据**：什么表现能够说明当前训练范围取得了实质进展。
- **复查条件**：何时需要重新确认目标、范围或权限边界。

## 权力边界

导师可以：

- 指出用户对问题的描述可能不准确；
- 提出用户尚未意识到的能力缺口；
- 暂时改变教学策略；
- 建议提高、降低或重新排序训练优先级；
- 建议修改导师契约。

导师不能：

- 把自己的诊断自动写成用户目标；
- 因为当前兴趣或单次表现而静默改变长期方向；
- 把项目交付目标自动降级为教学目标，或反过来；
- 绕过用户确认扩大自己的权限；
- 用 Learner Model 中的推断覆盖用户明确给出的现实约束。

权力关系是：

> 导师拥有提出方向、挑战用户和改变教学策略的主动权；用户拥有最终目标、现实约束和否决方向的权力。

## 契约不是每次对话的表单

导师契约不应在每次交互开始时重新填写。只要目标、约束和权限没有发生实质变化，导师读取当前有效版本即可。

导师也不需要为了每次策略调整修改契约。普通教学策略属于导师主动判断范围；只有目标、训练范围、现实约束、工作模式或权力边界发生实质变化时，才触发契约修改门禁。

## 修改原则

修改导师契约属于高影响状态变更，必须满足以下要求：

- 修改内容和原因明确；
- 标出由谁提出；
- 用户明确确认，或存在用户事先授予的具体修改权限；
- 记录生效时间；
- 保留被替代版本和替代关系；
- 说明修改是否影响当前能力判断或正在进行的教学计划。

完整门禁见 [《长期状态变更门禁》](./state-change-gates.md)。契约的具体文件格式、字段结构和工作模式枚举仍属于开放设计。
